# T-REX бэкап файловых баз 1С

**Версия 1.4.0 · Автор: Валентин Суровцев, 2026**

GUI-утилита для резервного копирования файловых баз 1С (WPF/XAML + PowerShell).
Полный цикл: копирование базы во временную папку (по умолчанию системная %TEMP%,
настраивается) → упаковка 7-Zip в
`<Имя>_<дата>_<время>.7z` → перенос в папку архивов → ротация старых архивов →
запись результата в логи (текстовый + SQLite).

## Запуск

- exe: `t-rex_backup1C.exe` (ярлык «T-REX бэкап файловых баз 1С» на рабочем столе);
- или скрипт: `pwsh -File .\backup-1c-gui.ps1` (работает и под Windows PowerShell 5.1).

Окно: **▶ СТАРТ** — бэкап всех баз из config.json; **■ СТОП** — мягкая остановка
после текущей базы (временные файлы будут удалены); **⚙** — настройки: папка
архивов, дни хранения, путь 7-Zip, каталог временных копий, список баз. Внизу окна
настроек — автор и версия.

## Каталог временных копий

Перед упаковкой каждая база копируется во временную папку (подпапка
`1c-backup_<дата>_<время>`, после прогона удаляется). По умолчанию это системная
`%TEMP%` — обычно на диске C:, где места может не хватать под копию большой базы.
Поле **«Каталог временных копий»** в настройках (поле `TempDir` в config.json)
позволяет указать другой диск/папку — например, `E:\Temp`: туда уходит и копия
базы, и архив до переноса в папку назначения.

- пустое поле / отсутствие `TempDir` = `%TEMP%`, как раньше (старые конфиги
  работают без изменений);
- если указанный каталог недоступен, прогон не начинается — в лог пишется ошибка
  (утилита не станет молча переполнять системный диск);
- при сохранении настроек несуществующий каталог предлагается создать.

## Тихий режим (для Планировщика Windows)

```
t-rex_backup1C.exe -Silent
```

Без окна обходит все базы из config.json и делает бэкап тем же конвейером, что и
в GUI. Логи те же: `backup_<дата>_<время>.log` и `backup_log.db` в папке архивов.

Коды возврата (в Планировщике видны как «результат последнего запуска»):

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | фатальная ошибка запуска (нет конфига, недоступна папка архивов, не найден 7-Zip) |
| 2 | прогон завершён, но есть неудачные базы |
| 3 | прогон прерван, обработаны не все базы |

## Расписание

Кнопка **⚙ → «Расписание…»**: составляется список расписаний, каждое — время
(ЧЧ:ММ) и дни недели. Утилита сама создаёт (или обновляет) задачу Планировщика
Windows «T-REX бэкап файловых баз 1С»: каждое расписание становится отдельным
триггером одной задачи. Например, «03:00 · ежедневно» + «15:30 · Пн Вт Ср Чт Пт» —
бэкап будет запускаться дважды в рабочие дни и один раз в выходные.

Работа со списком: «Добавить» открывает окно нового расписания, «Изменить» — окно
правки выбранной строки (без выбранной строки кнопка неактивна), «Удалить выбранное»
убирает строку. Любое из этих действий сразу применяется к задаче Планировщика —
отдельно подтверждать не нужно. При удалении последнего расписания программа спросит,
удалить ли задачу из Планировщика; «Удалить задачу» внизу убирает её целиком.
Если задача уже существовала — её расписание загружается в список при открытии окна.

Задача создаётся с параметрами безопасности «Выполнять **для всех пользователей**»,
«**Не сохранять пароль**» (доступны только локальные ресурсы компьютера) и «**Выполнить
с наивысшими правами**» — то есть бэкап срабатывает по расписанию независимо от того,
вышли вы из Windows или нет, и без хранения вашего пароля. Планировщик принимает такие
параметры только от процесса с правами администратора, поэтому при каждом изменении
расписания (и при удалении задачи) Windows показывает **запрос UAC** — подтвердите его
кнопкой «Да». Если сама утилита уже запущена от администратора, запрос не появляется.
Пропущенный по причине выключенного компьютера запуск выполняется при первой
возможности.

## Push-уведомления (ntfy)

После каждого прогона бэкапа на телефон приходит итог: **успех — тихий пуш** (без звука),
**ошибки или срыв — громкий**. В теле сообщения — строка по каждой базе из конфига:

```
НПД_БП — OK (НПД_БП_2026-09-13_03-00-00.7z)
ВестаПлюс_УТ — Ошибка (нет доступа к файлу 1Cv8.1CD)
Итог: OK — 1, ошибки — 1.
13.09.2026 03:05
```

Работает и в GUI, и в тихом режиме по расписанию. Канал — личный сервер ntfy: без Google,
без VPN, уведомления приходят и когда телефон просто в интернете. В заголовке каждого
уведомления — имя компьютера (`[ИМЯ-ПК] Бэкап 1С: …`): при установках в разные организации
сразу видно, с какой машины пришёл итог.

### Период наблюдения (при установке у заказчика)

Поле **«Дней наблюдения»** в настройках ограничивает, сколько дней от **первого прогона**
приходят итоги — удобно при внедрении: достаточно 10 дней убедиться, что всё работает,
затем уведомления отключатся сами. Отсчёт стартует с первого прогона после сохранения
(дата окончания пишется в config.json автоматически), в теле каждого итога видно, сколько
дней осталось («Наблюдение: до 28.09 (осталось 9 дн.)», «сегодня последний день»). Когда
срок истечёт, придёт **одно финальное уведомление** «Наблюдение завершено» — и наступит
тишина: бэкапы продолжают выполняться как обычно, меняются только уведомления.

- `0` или пустое поле = бессрочно (поведение прежних версий; старые конфиги без этого
  поля тоже работают бессрочно);
- **«Продлить с сегодня»** — перезапустить отсчёт заново (применится при сохранении);
- ввод **нового пароля** ntfy при сохранении тоже перезапускает отсчёт — это признак
  новой установки (на каждом новом компьютере пароль вводится заново, см. DPAPI ниже);
- кнопка «Отправить тест» и `-TestNotify` работают всегда, независимо от срока.

### Шаг 0. Сервер ntfy (если его ещё нет)

Подойдёт любой VPS за пределами РФ с Docker (у нас — FirstVDS, Амстердам). На сервере
однократно, под root (порт 2586 можно заменить на любой свободный):

```bash
mkdir -p /root/ntfy/cache /root/ntfy/etc && \
printf 'base-url: "http://IP-СЕРВЕРА:2586"\nlisten-http: ":80"\nauth-default-access: "deny-all"\ncache-file: "/var/cache/ntfy/cache.db"\nauth-file: "/var/cache/ntfy/user.db"\n' > /root/ntfy/etc/server.yml && \
docker run -d --name ntfy --restart unless-stopped \
  -v /root/ntfy/cache:/var/cache/ntfy \
  -v /root/ntfy/etc:/etc/ntfy \
  -p 2586:80 \
  binwiederhier/ntfy serve

# пользователь для отправки (пароль спросит дважды, ввод вслепую — это нормально):
docker exec -it ntfy ntfy user add --role=admin ИМЯ-ПОЛЬЗОВАТЕЛЯ
```

`auth-default-access: "deny-all"` закрывает сервер от посторонних: без логина нельзя ни
читать, ни писать. Проверка с компьютера — анонимные запросы должны получать отказ:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://IP-СЕРВЕРА:2586/   # 200 — сервер жив
curl -s -w '\n%{http_code}\n' -d test http://IP-СЕРВЕРА:2586/test  # 403 — чужим нельзя
```

Обслуживание: `docker restart ntfy`, лог `docker logs --tail 50 ntfy`, смена пароля
`docker exec -it ntfy ntfy user change-pass ИМЯ-ПОЛЬЗОВАТЕЛЯ`.

### Шаг 1. Приложение на Android

1. Установите **F-Droid** — магазин открытых приложений: скачайте APK с сайта
   `f-droid.org` (доступен из РФ), откройте файл, разрешите установку из этого источника.
2. Откройте F-Droid → поиск (лупа) → наберите **ntfy** → установите приложение ntfy
   (автор Philipp C. Heckel). Или прямая ссылка: `f-droid.org/ru/packages/io.heckel.ntfy/`.
   Версия именно из F-Droid: она умеет прямую мгновенную доставку со своего сервера,
   версия из Google Play работает только через push-серверы Google.
3. Откройте ntfy → «**+**» → **«Использовать другой сервер»** → заполните:
   - адрес сервера: **целиком со схемой** `http://IP-СЕРВЕРА:2586` (без `http://`
     приложение молча пробует https и уведомления не приходят — самая частая ошибка);
   - топик: `trex-alerts` (тот же, что в настройках утилиты);
   - логин и пароль, созданные на шаге 0.
4. Приложение попросит отключить оптимизацию батареи — согласитесь (иначе Android
   усыпляет доставку). Проверьте, что системные уведомления для ntfy разрешены.

### Шаг 2. Настройка в утилите

Окно настроек (⚙), секция «Push-уведомления ntfy»: галочка включения, адрес сервера
(`http://<IP>:<порт>` — целиком с `http://`), топик (по умолчанию подставляется
`trex-alerts`), логин и пароль. При включённой галке доступен выбор **способа отправки**
(поле `Mode` в config.json): «JSON на корень» — основной (все параметры в JSON-теле) и
«POST на топик (curl-стиль)» — запасной (тело — простой текст, приоритет и теги —
HTTP-заголовками); оба способа взаимозаменяемы и проверены на личном сервере. Отправки
через WebSocket в ntfy не существует — WebSocket используется только телефоном для
получения уведомлений. Кнопка **«Отправить тест»** шлёт проверочное уведомление
прямо из заполненных полей — без сохранения, выбранным способом. Пароль хранится в
config.json в зашифрованном виде (DPAPI, под вашу учётную запись Windows): на другом
компьютере или под другим пользователем его придётся ввести заново.

Проверка из командной строки: `t-rex_backup1C.exe -TestNotify` (или
`pwsh -File .\backup-1c-gui.ps1 -TestNotify`) — отправит тестовый пуш по данным из
config.json. Если уведомление не отправилось (сервер недоступен и т.п.), в лог прогона
пишется предупреждение — на сам бэкап это не влияет.

Полная техническая инструкция (интеграция в скрипты, ловушки API, диагностика) — в
`..\docs\ntfy-push.md`.

## Настройка (config.json)

Общий с консольным `backup-1c.ps1`. Поля:

| Поле | Смысл |
|---|---|
| `Destination` | папка для архивов |
| `KeepDays` | сколько дней хранить архивы; 0 = не удалять (бывшее «КоличествоДнейАктуальности» — старое имя по-прежнему читается) |
| `Bases` | список `{ Name, Path }` — имя для архива и путь (каталог базы или файл 1Cv8.1CD) |
| `SevenZipPath` | необязательно: путь к 7z.exe (по умолчанию автопоиск) |
| `TempDir` | необязательно: каталог временных копий баз перед упаковкой (по умолчанию системная %TEMP%; недоступный каталог — фатальная ошибка прогона) |
| `LogDb` | необязательно: путь SQLite-базы логов (по умолчанию `<папка архивов>\backup_log.db`) |
| `LogSqliteEnabled` | необязательно: `false` — не писать логи в SQLite вообще (остаётся только текстовый лог; чекбокс «БД логов (SQLite)» в настройках). Отсутствие поля = включено |
| `Ntfy` | необязательно: `{ Enabled, Url, Topic, User, PasswordEnc, Mode, WatchDays, ActiveUntil, FinalNoticeSent }` — push-итоги (пароль зашифрован; заполняется окном настроек). `Mode`: `json` (основной, отсутствует по умолчанию) или `topic` — способ отправки. `WatchDays` — период наблюдения (дней от первого прогона; 0/отсутствие = бессрочно), `ActiveUntil`/`FinalNoticeSent` — служебные поля срока (пишутся автоматически) |

Ротация старых архивов выполняется только если прогон прошёл без ошибок — при
сбое старые архивы остаются как страховка.

## Логи

- Текстовый: `<папка архивов>\backup_<дата>_<время>.log` — все события прогона.
  По окончании бэкапа предыдущие текстовые логи удаляются — остаётся только лог
  последнего прогона (SQLite-база при этом хранит всю историю).
- SQLite: `backup_log.db` — таблицы runs / run_results / rotation_events / bases.
  Последний запуск: `SELECT * FROM runs ORDER BY id DESC LIMIT 1;`
- Ошибки тихого режима, случившиеся до чтения конфига (папка архивов ещё
  неизвестна): `%TEMP%\T-REX-Backup1C-silent.log`.

## Зависимости

- 7-Zip (7z.exe).
- SQLite-драйвер встроен в скрипт/exe (распаковывается в
  `%LOCALAPPDATA%\T-REX-Backup1C`) — устанавливать ничего не нужно.
